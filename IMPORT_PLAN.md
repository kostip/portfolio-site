## Внешние ссылки и проблемы

- В кейсе AmeliSoul есть внешняя ссылка на User Flow в Figma. Она корректно оформлена в обоих экспортax.
- Ссылка Telegram на главной записана как `t.me/k0stip` без `https://`. В Markdown она воспринимается как относительный локальный путь, которого нет; в HTML Notion превратил её в неверный адрес `https://app.notion.comt.me/k0stip`. Будущий правильный адрес: `https://t.me/k0stip`.
- Email на главной записан как `http://versh.konstantin@gmail.com/`. Это веб-адрес, а не почтовая ссылка. Будущий правильный формат: `mailto:versh.konstantin@gmail.com`.
- В HTML главной страницы есть удалённая фоновая картинка с Unsplash. Она не сохранена локально, поэтому HTML зависит от интернета. Это не сломанная локальная ссылка, но для будущего сайта ресурс нужно будет либо сохранить отдельно, либо осознанно убрать/заменить.
- HTML-файлы также подключают служебный CSS KaTeX с CDN. Он относится к экспорту Notion, а не к содержимому портфолио.
- В HTML кейса OptimaServis встречается удалённый адрес Notion/S3 для иконки, при этом локальная копия иконки также присутствует в HTML-экспорте.

## Сравнение Markdown и HTML

### Текст

Основным источником текста лучше выбрать Markdown. В нём легко видеть и переносить заголовки, абзацы, списки, таблицы и ссылки; нет сотен строк служебных стилей и HTML-разметки Notion. Текст в обоих экспортax по содержанию соответствует друг другу.

### Структура

Для основной смысловой структуры лучше использовать Markdown: порядок разделов и уровни заголовков читаются явно. HTML полезно держать как контрольный образец — по нему можно уточнять визуальные особенности Notion, например колонки, подписи, иконки страниц и оформление отдельных блоков. Сам HTML не стоит напрямую переносить в сайт: он содержит большой встроенный набор стилей Notion и лишние служебные элементы.

### Изображения

Основные изображения кейсов одинаково представлены в обоих экспортax. В качестве полного каталога файлов лучше использовать HTML-экспорт: в нём есть четыре дополнительные иконки/аватарки страниц, отсутствующие в Markdown-экспорте (GOR, Браво-Оптика, OptimaServis и AmeliSoul). Для понимания места изображения в тексте удобнее ссылки из Markdown. Практический вариант будущего импорта: брать порядок и подписи из Markdown, а наличие и оригинальные файлы перепроверять по HTML-папке.

## Итоговая рекомендация для будущего импорта

1. Брать текст, заголовки, списки, таблицы и порядок блоков из Markdown.
2. Сверяться с HTML для визуальной структуры и элементов, которые Markdown не сохранил явно.
3. Брать изображения из HTML-экспорта как из более полного набора, сохраняя соответствие с местами вставки из Markdown.
4. Перед переносом переименовать будущие копии изображений латиницей и исправить Telegram/email; исходные экспортированные файлы оставить без изменений.
